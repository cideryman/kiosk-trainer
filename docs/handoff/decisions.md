# 안정된 결정과 변경 금지선

[핸드오프로 돌아가기](../../handoff.md)

## 데이터와 개인정보

- 간식 `제공대상`은 `user` 또는 `guest`만 사용하고 `both`는 사용하지 않습니다.
- 게스트 주문의 `userId`는 항상 `guest`로 저장합니다. 카카오 식별값으로 대체하지 않습니다.
- 카카오 원본 ID와 토큰은 Sheets에 저장하지 않고 솔트를 사용한 단방향 값 `guestKey`만 저장합니다.
- 브라우저가 보내는 `guestKey`는 인증 근거로 사용하지 않습니다. 카카오 코드 교환 뒤 GAS가 발급한 12시간 HMAC 증명에서 검증한 subject만 온기·프로필·주문·전체 주문 조회에 사용합니다.
- 기존 주문·후기·게스트 프로필 흐름에서는 실명, 이메일, 전화번호를 수집하지 않습니다.
- **이용 신청 예외**: `guest-apply.html`의 사전 이용 등록에서만 이름·관계·연락처·배달 장소·희망 요일을 수집할 수 있습니다. 관계 설명·상세 전달 방법·자유 메시지는 새 신청에서 받지 않습니다. 이 정보는 `이용신청` 시트와 인증된 관리자 신청 상세 화면에서만 사용하며 주문내역·주방·전광판·빌지·후기·관리자로그로 복사하지 않습니다. 이메일은 수집하지 않습니다.
- 이용 신청 개인정보는 브라우저 저장소에 보관하지 않고, 승인 신청은 이용 중 보관합니다. 반려·이용 중지 후 30일이 지나면 관리자가 만료 점검과 확인 문구를 거쳐 수동 익명화합니다.
- 신청자 상태 조회 페이지는 계정 없는 조회 토큰과 개인정보 노출 위험에 비해 초기 운영 효과가 작아 도입하지 않습니다. 승인·반려 결과는 기관 담당자가 직접 연락하고 관리자 화면의 `연락 완료`로 기록합니다.
- 이용 신청 설정의 `guestApplicationCapacity`는 주당 운영 안내 인원입니다. 신청·승인·주간 운영 인원을 제한하지 않으며, 관리자가 운영 규모를 안내하기 위한 숫자로만 사용합니다. 신규 신청은 정원과 관계없이 `PENDING`으로 접수하고, `WAITLIST`는 관리자가 직접 보류할 때만 사용합니다. 화면에서 `PENDING`은 '검토 중', `WAITLIST`는 '대기'로 표시합니다.
- 브라우저 저장소는 주문 편의, 중복 주문 방지, 주문 조회, 게스트 크레딧 중복 사용 방지에 필요한 값만 사용합니다.
- 로컬 게스트 표시명은 기기 안에 저장할 수 있지만 배달지, 실명, 연락처, 원본 카카오 ID, 크레딧은 새로 로컬 저장하지 않습니다.

## Sheets 구조 보호

- 실제 운영 DB 열을 코드 가정에 맞춰 임의로 이동하거나 삭제하지 않습니다.
- 운영 점검 경고만 보고 열을 재배열하지 않습니다. alias 호환과 최신 DB 헤더를 먼저 확인합니다.
- 시트 구조 보정이나 마이그레이션을 `onOpen` 또는 시간 기반 트리거에 연결하지 않습니다.
- 구조 변경은 백업 확보, 레이아웃 대조, 운영 중지 또는 낮은 운영 시간 확보 후 수동으로 실행합니다.
- 주문 보관은 주 1회 또는 `주문내역` 약 50행 이상을 권장하며 운영이 없는 시간에 주방 `운영 도구 > 지난 주문 보관`으로 수동 실행합니다.

## 주문 안정성

- 프론트 주문 버튼 잠금은 UX 방어선이며 서버 중복 방지의 대체물이 아닙니다.
- `placeOrder`는 `idempotencyKey`로 동일 요청 재전송을 식별하고 성공한 기존 주문 결과를 돌려줍니다.
- 정상적인 새 주문은 새 키를 만들기 때문에 차단하지 않습니다.
- 주문 성공 여부가 불명확한 네트워크 오류에서는 같은 키를 유지하고, 명확한 성공·실패 뒤에는 키를 폐기합니다.
- 최종 주문은 표시 캐시가 아니라 원본 Sheets의 재고, 판매상태, 크레딧을 다시 검증합니다.
- 트랜잭션 롤백과 부분 실패 복구는 멱등성과 분리합니다. 실제 불일치 증거 없이 대규모 구조를 도입하지 않습니다.

## 배송지 표시와 그룹화

- 배송지 그룹화에서 앞뒤 공백 제거와 연속 공백 정리는 적용할 수 있지만, 의미가 달라질 수 있는 유사어를 자동 병합하지 않습니다.
- `가족지원센터`와 `가족지원 센터`처럼 공백만 다른 표현은 같은 그룹으로 볼 수 있습니다.
- `여성센터`와 `여성 장애인 센터`, `원탁`과 `사무실 원탁`처럼 포함 관계가 있거나 실제 장소가 다를 수 있는 표현은 자동 병합하지 않습니다.
- 장소를 합쳐야 할 때는 관리자가 명시적으로 별칭을 등록하고, 그룹에는 운영자가 확인할 대표 표시명을 사용합니다.
- 주방 배달 그룹은 첫 주문이 들어온 순서를 기준으로 배치하며, 같은 정규화·별칭 키의 주문만 해당 그룹 안에서 합칩니다.

## 배달왔삼 UX와 운영

- 주문 시작 단계에서 `guestDeviceId` 또는 카카오 `guestKey` 기반 크레딧 조회를 유지합니다. 이는 새 화면이 아니라 백그라운드 조회입니다.
- 로컬 게스트 닉네임 입력은 주문 시작이 아니라 마지막 `주문자 정보` 영역에서 받습니다.
- 카카오 저장 프로필이 있으면 저장된 표시명을 사용하고 입력칸을 생략합니다.
- 영업 종료 중 메뉴 보기는 `menu.html?browse=guest` 읽기 전용 화면으로 제공하며 주문 세션, 크레딧, 장바구니를 만들지 않습니다.
- 예약 종료 전에 시작한 주문은 종료 후 5분까지 제출할 수 있습니다. 관리자의 즉시 마감은 진행 중 주문도 거절합니다.
- P99의 기존 설정은 Asia/Seoul 기준 수요일 13:00~15:00, 기본 OFF로 승계합니다. P102부터 정기 요일은 월~금 중 하나를 선택하고, 신청이 있는 날은 날짜당 1개의 추가 운영으로 등록합니다.
- 시간 트리거 없이 조회와 주문 시점에 서버가 판정하고 `placeOrder`의 동일 판정 결과를 최종 권한으로 사용합니다. 정기·추가·긴급 운영이 겹치면 가장 늦은 마감까지 운영합니다.
- 행사 모드에서는 정기·추가 운영을 억제하고 종료 시각 기반 긴급 운영만 사용합니다. 정기 회차 중단은 해당 정기 회차와 그 날짜의 긴급 운영만 막고 명시적인 추가 일정은 유지합니다.
- 즉시 마감은 활성 정기 회차를 중단하고 활성 추가 일정을 취소합니다. 자연 마감은 시작 주문에 5분 완료 유예를 주지만 즉시 마감에는 유예를 주지 않습니다.
- 새 주문 이메일 알림은 서버가 `userId === 'guest'`로 판정한 배달왔삼 포장·배달 주문에만 적용합니다. 일반 키오스크 주문은 설정이 ON이어도 이메일 큐에 넣지 않으며, 기존 설정 키·메일 형식·큐·재시도 트리거는 유지합니다.
- 마감 상태 API를 확인할 수 없으면 읽기 전용 메뉴 버튼을 노출하지 않습니다.
- **마스코트 캐릭터 및 대원 브랜딩 (P45)**: 배달왔삼의 발달장애인 배달 훈련 대원 공식 명칭은 **달곰이 대원**으로 정의합니다. 관련 마크업 및 안내 일러스트의 alt 텍스트, 1줄 프로필 카드 및 시각적 캐릭터 에셋(`dalgomi_heart.png`, `dalgomi_delivery.png`, `dalgomi_cheer.png`)을 적용하여 정체성을 활용합니다.
- **가상 화폐 및 거래 수단 명칭 일원화 (P45)**: 서비스 내 모든 거래 수단 명칭을 기존 '크레딧(Credit)' 및 동전(🪙)에서 **'온기(Warmth)' 및 하트(❤️)**로 통일합니다. 이는 발달장애인 훈련생의 사회경험 화폐 지불이라는 가치를 감성적으로 전달하고 무료 서비스의 가치를 승화시키기 위함입니다. 백엔드/DB 데이터 속성명(`user.credit` 등)은 시스템 호환성을 위해 유지하며 화면 레이블 및 UI 표시 100%를 '온기' 및 ❤️로 전환합니다.
- **일반 키오스크 1회 주문 한도 (P103)**: 보상체계를 운영하지 않는 동안 일반 이용자의 `credit`은 충전·소진되는 잔액이 아니라 매 주문마다 새로 적용되는 개인별 `1회 주문 한도`입니다. 일반 주문은 값을 영구 차감하거나 취소 시 환불하지 않습니다. 배달왔삼의 온기는 기존 지갑·차감·환불을 유지하며, 향후 보상체계를 도입할 때는 일반 주문 한도와 별도 데이터로 설계합니다.
- **후기 답글 및 소통 정책 (P22)**: 발달장애인 직원의 AAC 답글은 손님이 실제 작성한 후기에 대해서만 1:1로 응답합니다. 후기 미작성 주문에 대한 '선제 감사 인사'는 사용자 혼란 방지 및 소통의 진정성 보존을 위해 도입하지 않고 제외합니다. 메인 화면(`guest.html`)은 전체 소통 롤링 전광판으로 활용하며, '내 주문 확인하기'(`guest-orders.html`) 카드 하단에서 손님 본인 주문에 대한 1:1 답글을 전달합니다.

## 성능과 캐시

- 재고·크레딧·주문 원본 데이터를 긴 TTL로 캐시하지 않습니다.
- `getSnacks` 15초 캐시는 메뉴 표시용이며 변경 경로에서 즉시 무효화합니다.
- 주문 읽기 2초 캐시는 폴링 부하 완화용이며 주문 상태 변경 때 무효화합니다.
- 설정 캐시는 변경 API와 무효화가 항상 짝을 이뤄야 합니다.
- 성능만을 이유로 `placeOrder`의 락 범위나 처리 순서를 크게 바꾸지 않습니다.

## 화면과 관리 책임

- `admin.html`: 이용자, 간식, 크레딧, 간식 표시 순서, 배달왔삼 이용 신청 승인·개인정보 정리
- `kitchen.html`: 실시간 주문, 당일 통계, 인쇄, 주문 보관, 게스트 영업과 배달팀
- `reviews.html`: 후기 확인, 공개·숨김, 관리자 대리 답글
- 관리자·주방·후기 화면의 상단 하위 메뉴는 한 번에 하나만 열며 다른 상단 버튼, 바깥 클릭, 메뉴 선택, `Esc`에서 닫힙니다.
- 후기 답글은 관리자 후기 화면에서 교사가 의견을 취합해 대리 작성합니다. 주방 화면에서 훈련생이 직접 실시간 작성하는 흐름은 만들지 않습니다.

## 모바일 친화적 개발 원칙

최근 관리자·주방·후기 화면 개선에서 확인한 기준입니다. 새 기능이나 화면을 만들 때 기능 구현과 함께 반드시 검토합니다.

- **모바일을 기본 검토 범위에 포함**: 최소 390px와 320px에서 먼저 확인하고, PC 화면(관리자·후기 1200px, 주방 1400px) 회귀도 함께 확인합니다.
- **가로 넘침 금지**: 긴 문구, 입력창, 표, 버튼 때문에 수평 스크롤이 생기거나 글자가 세로로 쪼개지지 않도록 `min-width: 0`, 반응형 grid/flex, 말줄임 또는 짧은 라벨을 사용합니다.
- **중요도에 따른 화면 우선순위**: 주문 처리처럼 자주 쓰고 운영에 중요한 정보는 첫 화면에 유지합니다. 자주 수정하지 않는 설정은 탭, 접기·펴기, 별도 영역으로 분리해 핵심 업무를 아래로 밀어내지 않습니다.
- **표시 문구와 입력값 분리**: 제목은 짧게, 값은 다음 줄 또는 별도 영역에 배치합니다. 같은 의미를 반복하는 표현은 줄이고 필요한 경우 이모티콘과 짧은 텍스트를 함께 사용합니다.
- **터치 조작 안정성**: 주요 버튼은 모바일에서 충분한 높이와 간격을 확보하고, 한 행에 억지로 많은 버튼을 넣지 않습니다. 버튼 순서와 위치는 화면 폭이 바뀌어도 예측 가능해야 합니다.
- **기능 보존 우선**: 반응형 개편은 기존 API, DOM ID, 저장 함수, 자동 새로고침, 입력값 보호 로직을 우선 유지하고 표시 구조부터 변경합니다.
- **탭·접기 상태의 안전한 기본값**: 화면을 다시 열었을 때 주문·주요 운영 정보가 기본으로 보이게 합니다. 통계·재고·상세 설정은 필요할 때 열 수 있도록 하되, 자동 새로고침이나 데이터 조회를 방해하지 않습니다.
- **검증 체크리스트**: PC·390px·320px에서 줄바꿈, 수평 넘침, 터치 영역, 탭 전환, 입력 중 자동 새로고침, 데이터 갱신, 모달·버튼 회귀를 확인한 뒤 완료 처리합니다.

## 미디어와 정적 자원

- 관리자 신규 이미지 업로드는 브라우저에서 최대 800px, WebP 품질 0.82로 변환합니다. 애니메이션 GIF는 원본을 유지합니다.
- 주방 준비 보드 상품 이미지는 발달장애인 이용자가 작은 썸네일에서도 상품을 구분할 수 있도록 단순한 배경, 대표 상품 중심, 통일된 비율을 사용합니다. 이미지가 없어도 간식명과 수량만으로 준비할 수 있어야 하며, 상세 수칙은 [주방 준비 보드 시각자료 수칙](kitchen-prep-visual-guidelines.md)에 따릅니다.
- 주방 준비 보드의 TTS는 자동 재생이 아니라 사용자가 누르는 선택형 안내를 우선합니다. 읽기 대상은 개인정보 없는 간식명과 총수량이며, 이미지·주문자·배달지는 읽지 않습니다.
- 웹폰트 CDN을 사용하지 않습니다. 기기에 Pretendard가 있으면 사용하고 없으면 시스템 한글 폰트로 대체합니다.
- 정적 파일을 바꾸면 서비스 워커 캐시 버전을 검토합니다.
