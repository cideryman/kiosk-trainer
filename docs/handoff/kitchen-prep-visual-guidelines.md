# 주방 준비 보드 시각자료 수칙

## 목적

주방에서 발달장애인 이용자가 주문 간식을 빠르게 구분하고 준비할 수 있도록, 기존 주문 처리 구조를 유지한 채 `지금 꺼내올 간식` 요약 보드에 상품 이미지를 보조 정보로 표시한다.

이 문서는 상품 이미지를 제작·등록하는 운영자와 향후 화면을 수정하는 개발자가 함께 지켜야 하는 기준이다.

## 이미지 제작 원칙

- 상품 하나가 화면의 중심에 오도록 촬영하거나 제작한다.
- 배경은 단순하고 밝게 유지하며, 불필요한 장식·소품·손·사람을 최소화한다.
- 작은 썸네일에서도 상품의 대표 색상과 모양이 구분되어야 한다.
- 비슷한 상품은 포장 색상, 대표 재료, 컵·봉지 모양 등 한 가지 이상의 시각적 차이를 분명히 한다.
- 이미지 안에 긴 설명 문구를 넣지 않는다. 상품명은 화면 텍스트로 제공한다.
- 모든 상품 이미지는 가능한 한 같은 비율, 같은 방향, 비슷한 여백으로 맞춘다.
- 사진이 흐리거나 과도하게 어둡거나 반사광 때문에 상품이 가려지지 않도록 한다.
- 이미지가 없거나 불러오기에 실패해도 주문명과 수량만으로 준비할 수 있어야 한다.

## 파일·성능 기준

- 관리자 업로드 변환 규칙인 최대 800px, WebP 품질 0.82를 유지한다.
- 준비 보드에서는 원본이 아니라 Drive 썸네일 URL을 사용한다.
- 보드의 썸네일은 모바일 기준 약 48~56px로 고정한다.
- 이미지 로딩 실패 시 깨진 이미지 아이콘을 노출하지 않고 텍스트 레이아웃으로 대체한다.
- 상품 이미지 URL이나 주문 구조를 새로 저장하지 않고, 기존 `간식목록`의 `imageUrl`을 재사용한다.

## 주방 화면 표시 원칙

- `지금 꺼내올 간식` 요약 보드에만 이미지를 우선 적용한다.
- 각 항목은 `이미지 · 간식명 · 총수량`을 한 덩어리로 표시한다.
- 수량은 이미지보다 시각적으로 두드러지게 유지한다.
- 개별 주문 목록은 기존 주문자·주문번호·간식명·수량·포장/배달·제공 처리 흐름을 유지한다.
- 개별 주문 카드에 큰 이미지를 반복해서 넣지 않는다. 필요성이 확인될 때만 작은 아이콘 또는 썸네일을 별도 검토한다.
- 요약 보드를 클릭해 여는 모달은 1차 범위에서 만들지 않는다. 준비자는 화면을 보며 바로 꺼낼 수 있어야 하며, 모달은 한 번 더 조작해야 하기 때문이다.
- 인쇄 기능도 1차 범위에서 만들지 않는다. 주문량이 적은 시범 운영에서 화면 표시로 충분한지 먼저 확인하고, 반복적인 종이 출력 필요성이 확인될 때 별도 설계한다.

## 선택형 TTS 원칙

- 자동 재생은 기본값으로 두지 않는다.
- 요약 보드에 수동 `🔊 간식 읽어주기` 버튼을 두는 방식을 우선 검토한다.
- 읽기 내용은 주문자·배달지 없이 간식명과 총수량만 사용한다.
- 예: `콤부차 자두 7개, 커피믹스 3개입니다.`
- 읽기 시작 전에 기존 음성을 중지하고, 연속 클릭으로 음성이 겹치지 않게 한다.
- 이미지가 없거나 일부 상품명이 비어 있어도 텍스트 목록을 기준으로 읽는다.
- 자동 TTS는 실제 운영에서 수동 TTS가 유용하다고 확인된 뒤, 새 주문 감지와 중복 재생 방지 조건을 별도로 설계한다.

## 접근성·검증 기준

- 상품 이미지가 없어도 핵심 정보가 손실되지 않아야 한다.
- 색상만으로 상품을 구분하지 않는다.
- PC와 390px·320px 모바일에서 이미지, 상품명, 수량이 겹치거나 수평 스크롤을 만들지 않아야 한다.
- 실제 준비자가 이미지와 텍스트를 함께 보고 간식을 구분할 수 있는지 확인한다.
- 이미지가 잘못 연결되었을 때 텍스트 상품명이 최종 판단 기준이 되도록 한다.
