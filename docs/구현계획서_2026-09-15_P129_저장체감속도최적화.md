## 1. 개요 및 배경

운영설정(`settings.html`) 및 관리자(`admin.html`) 화면에서 설정이나 데이터를 수정한 뒤 저장할 때 발생하는 **3~5초 멈칫거림/지연** 현상을 해결합니다.

원인은 크게 두 가지입니다:
1. **`alert()` 동기 블로킹**: 저장 성공/실패마다 브라우저 네이티브 `alert()` 모달이 뜨며 사용자가 [확인]을 누를 때까지 UI 스레드가 정지됨.
2. **불필요한 동기 전체 재조회**: 저장 직후 `await loadAllSettings()` / `await loadAdminData()`를 호출하여 서버 전체 데이터를 다시 쿼리함 (~1.5초 소요).

## 2. 변경 계획 (Proposed Changes)

### 1. 공통 유틸리티 — 인라인 버튼 성공 피드백

#### [MODIFY] [js/settings.js](../js/settings.js)

새 함수 `setButtonSuccess(button, text, durationMs)` 추가 (기존 `setButtonLoading` 바로 아래):

```javascript
function setButtonSuccess(button, text = '✓ 저장 완료', durationMs = 1500) {
  if (!button) return;
  button.disabled = true;
  button.classList.add('is-success');
  button.textContent = text;
  setTimeout(() => {
    button.disabled = false;
    button.classList.remove('is-success');
    if (button.dataset.originalText) {
      button.textContent = button.dataset.originalText;
    }
  }, durationMs);
}
```

> [!IMPORTANT]
> `setButtonLoading`이 `button.dataset.originalText`를 저장하고 있으므로 `setButtonSuccess`는 이 값을 그대로 활용합니다. `setButtonLoading(btn, false)`로 복원한 **뒤에** `setButtonSuccess`를 호출하는 순서를 지킵니다.

대상 핸들러:

5. `deleteGuestAdditionalScheduleAction` (추가 운영 일정 삭제)
6. `guestEmergencyOpenUntilAction` (긴급 운영 시작)
7. `guestEmergencyCloseAction` (긴급 운영 조기 마감)
8. `saveCapacityAction` (정원 및 배달 설정)
9. `saveBaseSettingsAction` (기본 운영 설정)
10. `saveEventSettingsAction` (행사 모드 설정)

**구체적 최적화 방향:**
1. **성공 시 `alert()` 제거** → `setButtonSuccess(btn, '✓ 완료')` 인라인 피드백 적용
2. **값 설정 계열 4개 핸들러** (`saveKioskPolicyAction`, `saveCapacityAction`, `saveBaseSettingsAction`, `saveEventSettingsAction`):
   - `await loadAllSettings()`를 완전히 제거하고 로컬 `latestGuestOpsSettings` 객체에 저장한 값을 즉시 `Object.assign`
3. **일정/운영 계열 6개 핸들러** (`saveGuestWeeklyScheduleAction`, `toggleGuestWeeklyScheduleSkipAction`, `addGuestAdditionalScheduleAction`, `deleteGuestAdditionalScheduleAction`, `guestEmergencyOpenUntilAction`, `guestEmergencyCloseAction`):
   - 서버가 다음 운영 일정, 스킵 상태, 운영 출처 등을 재계산하므로 UI는 즉시 성공 처리하고, `loadAllSettings()`는 `await` 없이 백그라운드 무소음 호출
4. **실패/에러 시 `alert()` 유지**: 오류 메시지는 사용자가 인지해야 하므로 기존대로 유지
