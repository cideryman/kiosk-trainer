## 0. 새 신청서 반영 요약

이번 신청서는 2027년 1월 1일부터 12월 31일까지 12개월 운영을 전제로 하며, 기존 검토서보다 운영 수치와 평가 방법이 구체화되었다.

| 구분 | 확정 내용 | 시스템 검토에 미치는 영향 |
|---|---|---|
| 핵심 참여자 | 성인 발달장애인 8명 | 기존 `이용자목록`과 별도로 사업 참여자 ID·역할 이력이 필요 |
| 주변 참여자 | 배달왔삼 이용자 실인원 50명, 찾아가는 카페차 이용자 30~60명 | 신청자·운영회차·카페차 참여 실적을 분리 집계해야 함 |
| 교육·실습 | 집중교육 12회, 핵심 참여자 연인원 96명 | 교육 일정·출석·주제·실습 결과 기록이 필요 |
| 배달왔삼 운영 | 초기 적응 4회 + 정기 26회 = 연간 30회 | 운영회차를 30개 회차로 구분하고 회차별 참여·주문·역할을 연결해야 함 |
| 제공량 | 총 500잔·인분 이내, 신청 1건 기본 3잔, 단체 신청 최대 5잔 협의 | 신청·주문 제한과 실제 제공량을 별도 사업 실적으로 집계해야 함 |
| 관계 이어가기 | 후기 안내·확인 30회, TTS·AAC 답글 20회 이상, 서비스팀 회의 10회 | 후기·TTS·AAC·회의 활동을 사업회차와 연결해야 함 |
| 다회용 컵 | 일련번호가 있는 로고 컵 70개, 회수·세척·재사용 | 단순 수량이 아닌 컵별 상태·이력 관리가 필요 |
| 찾아가는 카페차 | 상반기·하반기 각 1회, 총 2회, 회당 30명 | 기존 검토서의 1회 표기를 2회로 수정하고 행사 회차·장소·참여 실적을 관리해야 함 |
| 성과평가 | GSE 1월·11월, 역할수행 사전·중간·사후, 변화 사례 8건 | 평가 시기·문항·관찰 회차·사례 근거를 구조화해야 함 |

### 신청서 내용과 현재 시스템의 표현 차이

신청서는 참여자별 역할 및 지원 수준을 지속 기록할 수 있다고 설명하지만, 현재 배달왔삼 코드가 실제로 보관하는 것은 주문·제공·후기·재고·운영설정 중심이다. `운영 담당`도 현재는 문자열 안내에 가깝고, 참여자 ID·회차·역할수행 지원 수준과 연결되지 않는다.

따라서 사업관리 기능이 구현되기 전에는 다음을 구분해서 표현해야 한다.

- **현재 지원**: 신청, 주문, 주방 처리, 포장·배달 상태, 후기·답글, TTS, AAC, 온기보드, 운영 통계
- **사업 수행을 위해 추가 기록이 필요한 기능**: 회차, 참여자 배정, 역할 이력, 지원 수준, 교육 출석, GSE, 컵 이력, 회의, 현장점검, 변화 사례

신청서의 “지속적으로 기록하여 사업 운영과 성과관리에 활용”이라는 문장은 위 사업관리 계층을 별도로 구축하거나 담당자가 보조 기록한다는 전제가 필요하다. 기존 주문 시스템이 자동으로 모든 성과자료를 기록한다고 해석되지 않도록 운영계획과 구현 범위를 함께 관리한다.

## 1. 검토 결론

현재 배달왔삼은 `이용 신청 → 주문 → 주방 처리 → 포장·배달 → 후기·답글`로 이어지는 실제 서비스 운영 흐름을 상당 부분 지원한다. 이용 신청의 정원·대기자 관리, 주문 상태와 재고 관리, 빌지·라벨 출력, 후기 공개와 TTS·AAC 답글, 온기보드, 행사 모드도 이미 갖추고 있다.

프로포절 실행을 위해 가장 크게 보완해야 하는 부분은 주문 기능이 아니라 **사업관리와 성과관리 기능**이다. 현재 시스템만으로는 핵심 참여자가 어떤 회차에서 어떤 역할을 맡았는지, 어느 정도의 지원을 받아 수행했는지, 시간이 지나며 어떤 변화가 있었는지를 체계적으로 기록하기 어렵다.

따라서 기존 주문 흐름은 안정적으로 유지하고, 별도의 `사업관리` 계층을 추가하는 방향을 권장한다.

## 3. 현재 시스템과 프로포절 사이의 핵심 격차

### 3.1 참여자별 역할 이력이 없다

현재 `운영 담당`은 배달 담당과 상품 준비 담당 이름을 표시하는 용도다. 이름이 문자열로 저장되며 이용자 ID, 운영회차, 실제 수행 결과와 연결되지 않는다. 프로포절에서 제시한 주문 확인, 계량, 혼합, 제조, 포장, 검수, 배달, 인사, 후기 확인과 답글 역할을 증빙하려면 참여자별 역할 이력이 필요하다.

### 3.2 지원 수준과 변화 과정을 기록할 수 없다

프로포절은 다음 4단계로 역할수행 지원 수준을 평가한다.

1. 전적인 신체적·언어적 지원이 필요함
2. 단계별 지속적인 언어·시각적 지원이 필요함
3. 일부 확인이나 촉진을 받으면 수행함
4. 준비된 환경에서 독립적으로 수행함

현재 DB에는 이 평가를 저장할 구조가 없다. 사전·중간·사후 변화와 참여자별 사례를 만들기 위해서는 회차별 관찰 기록이 필요하다.

### 3.3 실인원과 연인원을 안정적으로 계산하기 어렵다

개인정보 보호를 위해 이용 신청 정보와 주문 정보는 의도적으로 분리되어 있다. 이 원칙은 유지해야 하지만, 현재 상태로는 신청자·실제 이용자·재이용자를 정확하게 연결하기 어렵다.

이름이나 연락처를 주문에 복사하지 않고, 임의의 `programParticipantId`를 이용하여 신청·운영회차·주문을 연결하는 방식을 권장한다.

### 3.4 일일 운영 통계는 있으나 사업성과 통계가 없다

현재 통계는 당일 주문과 간식·이용자별 주문 건수를 확인하는 데 적합하다. 프로포절에 필요한 교육 횟수, 회차 수, 참여 실인원·연인원, 역할수행 변화, 후기 확인, TTS·AAC 답글, 회의, 협력기관 점검과 사례 수는 별도 집계가 필요하다.

## 4. 필수 기능

### 4.1 운영회차 관리

정기 배달, 교육·실습, 서비스팀 회의, 찾아가는 카페차를 하나의 회차 체계로 관리한다.

신청서의 운영 구조에 맞춰 운영 유형을 최소한 `집중교육`, `초기 적응 배달`, `정기 배달`, `서비스팀 회의`, `찾아가는 카페차`, `성과공유`로 구분한다. 초기 적응 배달 4회와 정기 배달 26회는 모두 배달왔삼 운영회차로 집계하되, 평가·지원 강도와 실적 보고에서는 구분할 수 있어야 한다.

권장 항목:

- 회차 ID, 날짜, 운영 유형, 장소와 협력기관
- 준비·진행·완료·취소 상태
- 핵심 참여자 명단과 주변 참여자 수
- 신청자 또는 단체 배정
- 주문·후기·컵 관리 기록 연결
- 활동사진, 운영 메모와 특이사항
- 회차별 제공 수량과 기본 3잔·단체 최대 5잔 기준

### 4.2 핵심 참여자 프로필과 역할 배정

기존 이용자목록과 개인정보를 직접 확장하기보다 사업용 참여자 프로필을 별도로 관리한다.

권장 항목:

- 참여자 ID와 기존 이용자 ID 연결
- 선호 역할, 강점, 지원 필요사항
- 기본 의사소통 방식과 AAC 지원 방법
- 촬영·성과홍보물 활용 동의 범위
- 회차별 계획 역할과 실제 수행 역할
- 핵심 역할 1~2개와 평가 대상 기간
- 쉬운 글·그림·음성·실제 시연 등 지원 방법

### 4.3 역할수행 관찰 체크리스트

주문 카드마다 평가를 요구하면 실제 운영이 느려질 수 있다. 운영 중에는 역할 완료 여부만 간단히 확인하고, 회차 종료 시 참여자별 대표 역할 1~2개를 평가하는 방식을 권장한다.

기록 항목은 계획 역할, 실제 역할, 4단계 지원 수준, 잘된 점, 어려웠던 점, 다음 지원 방법으로 제한한다.

### 4.4 교육·실습 기록

오리엔테이션, 위생·안전·고객응대, 주문 시스템 활용, 표준 음료 제조·계량·포장·전달 실습을 기록한다.

- 교육 주제와 목표
- 참석자와 출석 여부
- 담당자와 외부 강사
- 그림 레시피·작업 순서표·음성 안내 자료
- 실습 결과와 반복교육 필요사항
- 교육·실습 사진과 증빙 파일

### 4.5 성과평가와 KPI 대시보드

다음 목표는 수기 재계산 없이 확인할 수 있어야 한다.

| 지표 | 연간 목표 |
|---|---:|
| 집중교육 | 12회, 핵심 참여자 연인원 96명 |
| 배달왔삼 운영 | 초기 적응 4회 + 정기 26회 = 30회 |
| 배달 제공량 | 총 500잔·인분 이내 |
| 핵심 참여자 정기 운영 참여 | 연인원 240명 |
| 주변 참여자 | 실인원 50명, 서비스 이용 연인원 90~150명 |
| 후기 안내·확인 | 30회 |
| TTS 청취·AAC 답글 | 20회 이상 |
| 서비스팀 회의 | 10회 |
| 신규 운영장소 현장점검 | 협력기관별 사전협의 및 신규 운영장소별 1회 이상 |
| 참여자 변화 사례 | 8건 이상 |
| 찾아가는 카페차 | 2회, 상반기·하반기 각 1회 |
| 성과회보·성과공유회 | 각 1회 |

GSE는 성인용 10문항·4점 척도의 응답과 총점을 저장하고, 1월 사전검사 대비 11월 사후검사의 8명 평균이 10% 이상 향상되는지 계산한다. 문항은 읽어주고 응답 선택을 지원하되, 응답은 참여자 본인의 의사에 따라 기록해야 한다.

역할수행 지원 수준은 참여자별 핵심 역할 1~2개를 선정하여 사전·중간·사후에 같은 기준으로 관찰한다. 각 시기에는 초기 적응 또는 정기 운영 중 4회 관찰하고, 평균의 소수점 이하는 버려 대표 단계로 기록한다. 신청서의 핵심 성과목표는 8명 중 6명 이상이 사전 대비 1단계 이상 향상되는 것이다.

추가 성과목표인 “서비스 제공자로서 역할과 기여를 인식·표현하는 변화”는 역할 선택, 자발적 의사표현, 인사·전달·후기·답글 소통, 자신이 타인에게 도움이 되었음을 표현한 말·선택·행동을 동일한 질문과 관찰 항목으로 사전·중간·사후 기록한다. 8명 중 6명 이상을 목표로 하며, 후기·답글·보호자 및 이용자 의견을 사례 근거로 연결한다.

### 4.6 다회용 컵 관리

프로포절에 개별 번호 부여가 명시되어 있으므로 단순 수량 기록보다 컵별 이력이 적합하다.

- 컵 번호와 사용 가능 상태
- 제공 회차와 이용자 또는 기관
- 대여·회수·세척·재사용 일시
- 분실·파손·폐기 사유
- 회차별 회수율

### 4.7 협력기관·운영장소 관리

- 기관명, 담당자, 연락처와 운영장소
- 접근성, 전기·용수, 위생, 안전 점검표
- 협의 내용과 운영 가능 인원
- 방문·배달·카페차 운영 이력
- 참여자와 이용자 의견

## 5. 권장 화면 구성

관리자 사이드바에 `사업관리`를 독립 메뉴로 추가하고 다음 탭으로 구성하는 방안을 권장한다.

| 탭 | 주요 기능 |
|---|---|
| 운영회차 | 일정, 신청자 배정, 참여자 명단, 운영 결과 |
| 역할·관찰 | 역할 배정, 완료 확인, 지원 수준 평가 |
| 교육 | 교육 일정, 출석, 자료, 실습 결과 |
| 성과 | 목표 대비 실적, GSE, 변화 사례, 보고서 내보내기 |
| 협력·컵 | 협력기관·장소 점검과 다회용 컵 관리 |

주방 화면에는 별도의 복잡한 평가표를 넣지 않는다. 상단에 `오늘 회차`, 참여자와 역할을 보여주고, 운영 종료 시 관찰 기록으로 이동할 수 있는 버튼 정도만 제공한다.

## 6. 권장 데이터 구조

기존 주문·후기 시트의 열을 크게 변경하지 않고 다음 시트를 추가하는 방식이 안전하다.

| 신규 시트 | 역할 |
|---|---|
| `사업참여자` | 핵심 참여자의 사업용 프로필, 강점, 선호 역할, 동의 범위 |
| `운영회차` | 교육·정기배달·회의·행사 일정과 운영 결과 |
| `회차참여` | 회차별 핵심·주변 참여자 출석과 익명 연결 ID |
| `역할수행` | 참여자별 역할 배정, 완료 여부, 지원 수준과 관찰 메모 |
| `성과측정` | GSE, 면담, AAC 응답, 사전·중간·사후 평가 |
| `컵관리` | 컵 번호별 대여·회수·세척·상태 이력 |
| `협력기관` | 기관·장소 정보와 접근성·위생·안전 점검 |
| `사업회의` | 회의록, 결정사항, 담당자와 후속 조치 |

개인정보는 현재 이용신청 시트에 유지하고, 다른 시트에는 익명 ID만 전달한다. 활동사진과 성과자료는 공개 범위와 동의 상태를 함께 저장한다.

## 7. 단계별 구현 우선순위

### 1단계: 정기 운영 전에 필요한 기반

- 운영회차 생성과 신청자 배정
- 핵심 참여자 프로필과 역할 배정
- 역할수행 4단계 관찰 기록
- 익명 참여 ID 연결
- 기본 KPI 집계

### 2단계: 1~3월 교육·초기 적응 운영

- 교육 일정·출석·증빙 관리
- 역할별 그림 레시피와 음성 안내
- GSE 사전검사와 초기 수행 수준 입력
- 회차 종료 관찰 기록 UX

### 3단계: 정기 운영과 지역사회 확장

- 다회용 컵 관리
- 협력기관·장소와 안전점검
- 서비스팀 회의록과 후속 조치
- TTS·AAC 활동 참여자 및 횟수 기록

### 4단계: 7월 중간평가와 11월 성과공유 전

- 중간·사후 평가 비교
- 목표 대비 실적 대시보드
- 참여자별 변화 사례 정리
- 엑셀·CSV 내보내기
- 상반기·하반기 찾아가는 카페차 2회 운영 결과와 성과자료 관리

## 8. 초기 범위에서 제외해도 되는 기능

- 전체 교육과정을 제공하는 별도 LMS
- 자동 카카오톡·문자 승인 알림
- 모든 주문 단계에 복잡한 평가 상태를 추가하는 기능
- 참여자가 혼자 수행해야 하는 온라인 GSE 검사
- 회계·예산 집행을 위한 별도 ERP

초기에는 담당자가 보조하여 기록하되, 시스템은 누락 방지, 일관된 관찰, 자동 집계와 증빙 생성에 집중하는 것이 적절하다.

## 9. 구현 전 확인사항

1. 2027년 1월 1일~12월 31일 사업기간, 초기 적응 4회·정기 26회·카페차 2회와 평가 문항을 기준으로 데이터 계약을 확정한다.
2. 핵심 참여자 8명의 역할 범위와 4단계 평가 기준을 역할별로 구체화한다.
3. GSE 10문항의 사용·보관 방식, 1월·11월 측정 절차, 사진·영상 활용 동의서를 확인한다.
4. 실인원·연인원 산정 기준과 취소·부분 참여 처리 기준을 정한다.
5. 일련번호가 있는 다회용 컵 70개의 번호 체계와 회수·세척·건조·재사용 상태 기록 방식을 결정한다.
6. 공동모금회 결과보고서에 필요한 표와 증빙 형식을 미리 확인한다.

이 확인사항이 정리된 뒤 1단계 데이터 계약과 화면 구조를 먼저 설계하고, 기존 주문 시스템과 분리된 작은 단위부터 구현한다.

## 10. 프로포절과 무관한 배달왔삼 운영 기능 우선순위

프로포절 선정 여부와 관계없이 배달왔삼은 계속 운영할 수 있으므로, 사업보고용 기능과 실제 운영에 직접 도움이 되는 기능을 분리해서 판단한다.

### 10.1 운영 기능으로 추가할 가치가 큰 항목

#### 배달 담당·상품 준비 담당 표시

오늘 누가 배달을 담당하고 누가 상품을 준비하는지 주방에서 바로 확인할 수 있으면 역할 분담과 운영 책임이 명확해진다. 프로포절의 성과평가나 역할수행 기록과 연결하지 않아도 매 운영일에 유용한 기능이다.

초기 범위는 복잡한 참여자 이력보다 다음 수준으로 제한하는 것을 권장한다.

- 오늘의 배달 담당 표시
- 오늘의 상품 준비 담당 표시
- 운영설정에서 담당자 문구 저장
- 주방 화면과 필요한 안내 영역에 동일하게 표시

참여자 ID, 회차별 실제 수행 결과, 지원 수준 평가는 별도 사업관리 기능으로 분리하고 첫 버전에 섞지 않는다.

#### 다회용 컵 관리

실제로 다회용 컵을 운영한다면 프로포절과 관계없이 운영 가치가 있다. 다만 처음부터 70개 컵을 모두 개별 추적하면 담당자의 기록 부담이 커질 수 있으므로, 1단계는 수량 중심으로 시작한다.

- 대여 수량
- 회수 수량
- 미회수 수량
- 세척 완료 수량
- 분실·파손 메모

실제 미회수나 분실 문제가 반복될 때 컵 번호별 이력과 QR·바코드 추적을 추가한다.

#### 함께 우선 검토할 운영 기능

- 배송지별 배달 체크리스트와 미배송·미회수 예외 표시
- 주문 마감·배달팀·운영 메모 관리
- 간식 이미지가 포함된 준비 보드와 선택형 TTS
- 재고 부족·품절 표시
- 주문·제공·취소 상태 관리
- 하루 운영 결과 요약
- 주소 확인 필요, 재료 부족, 재배달 필요 같은 운영 특이사항 메모

### 10.2 별도 양식으로 유지하는 편이 나은 항목

다음 항목은 기관 양식이나 담당자 문서가 이미 있을 가능성이 높고, 배달왔삼에 넣으면 개인정보와 관리 복잡성이 커질 수 있다.

- 서비스팀 회의록
- GSE 문항과 평가 결과
- 보호자 상담 기록
- 장문의 변화 사례
- 사진·영상 증빙 관리
- 성과회보 작성
- 예산·회계 관리

### 10.3 운영 기준 권장 순서

1. 오늘의 배달 담당·상품 준비 담당 표시
2. 다회용 컵 수량 중심 관리
3. 배송지별 체크리스트와 미배송·미회수 예외 표시
4. 하루 운영 결과 요약과 운영 통계 정리
5. 운영 메모·특이사항 기록
6. 실제 필요성이 확인된 뒤 컵 번호별 상세 추적

이 기준은 프로포절 기능을 배제하는 것이 아니라, 먼저 매 운영일의 안정성과 편의성을 높이고 이후 사업관리 기능을 별도 계층으로 확장하기 위한 운영 원칙이다.
