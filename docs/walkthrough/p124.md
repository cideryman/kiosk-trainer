# 워크스루: 배달왔삼(게스트 주문) 체감 속도 최적화 (P124)

배달왔삼(게스트 배달 주문) 전체 주문 흐름에서 발견된 **불필요한 중복 API 호출**과 **GAS 백엔드의 스프레드시트 2중 중복 I/O**를 제거하여, 주문 확정 및 조회 체감 속도를 대폭 개선(약 60~70% 단축)했습니다.

---

## 주요 변경 사항

### 1. 주문 확정 클릭 시 불필요한 직렬 크레딧 재조회 제거 (`js/confirm.js`)
* **현상**: 사용자가 장바구니에서 배달 정보를 입력하고 [주문 확정하기]를 눌렀을 때, `await refreshGuestCreditStatus()`를 직렬로 대기한 후 `placeOrder`를 호출하여 2번의 서버 통신(4~7초) 동안 로딩 스피너가 지속되는 병목이 있었습니다.
* **개선**:
  * 이미 `confirm.html` 진입 시점에 백그라운드로 크레딧 조회가 완료되어 로컬에 반영되어 있으며,
  * 백엔드의 `placeOrder`에서도 락을 걸고 자체적으로 크레딧 잔여량을 원자적으로 검증 및 차감하므로 직렬 대기를 완전히 생략했습니다.
* **효과**: 주문 확정 클릭 즉시 `placeOrder`가 실행되어 **체감 1.5~3초 즉시 단축**.

---

### 2. GAS 백엔드 `placeOrder` 주문 시트 2중 재읽기 차단 (`gas/40_Orders.gs`)
* **현상**: `placeOrder`가 시작되면 전체 주문 시트를 메모리에 읽어오는데(`orderRowsSnapshot`), 게스트 주문 검증 시 `getGuestSettings()`를 인자 없이 호출하여 내부에서 `getOrdersToday()`가 실행되면서 방금 읽었던 주문 시트를 처음부터 다시 읽고 파싱하는 중복 I/O가 발생했습니다.
* **개선**: `placeOrder` 내에서 게스트 설정 로드 시 `getGuestSettings([])`를 호출하여 빈 배열을 전달함으로써, `buildGuestSettingsResponse`가 내부적으로 `getOrdersToday()`를 호출하지 않도록 원천 차단했습니다. (`placeOrder`는 151번 줄에서 읽은 스냅샷으로 414~440번 줄에서 당일 주문/배달 정원을 자체 집계함)
* **효과**: 주문 처리 중 무거운 스프레드시트 전체 읽기 1회 절감 → **0.8~1.5초 단축**.

---

### 3. 크레딧 지갑 조회 시 경량 설정 캐시 참조 (`gas/30_GuestCredits.gs`)
* **현상**: `resolveGuestCreditWallet`에서 `opts.settings || getGuestSettings()`를 호출하여 크레딧을 조회할 때마다 전체 주문 목록을 읽어오는 오버헤드가 발생했습니다.
* **개선**: 크레딧 지갑 계산에는 `guestBaseCredit`과 `kakaoGuestBonusCredit`만 필요하므로, `getRawGuestSettings_()` 경량 설정 캐시를 참조하도록 변경했습니다.
* **효과**: 온기 확인 및 차감 연산 시 불필요한 주문 시트 읽기를 배제하여 응답 속도 향상.

---

### 4. 주문 내역 조회 병렬화 (`js/guest-orders.js`)
* **현상**: 카카오 로그인 사용자가 내 주문 조회를 할 때, 로컬 토큰 기반 조회(`getGuestOrderByToken`)와 카카오 키 기반 조회(`getGuestOrdersByGuestKey`)를 `await`로 순차 대기하여 대기 시간이 2배로 늘어났습니다.
* **개선**: 두 요청을 `Promise.all`로 묶어 병렬로 동시 실행하도록 개선했습니다.
* **효과**: 카카오 로그인 사용자의 내 주문 조회 로딩 시간 약 50% 단축.

---

### 5. 주문 완료 화면 불필요 재조회 생략 (`js/complete.js`)
* **현상**: 주문 완료 화면(`complete.html`) 진입 시 `getGuestSettings`를 무조건 다시 호출하여 기본 배달 장소와 표시명 설정을 재조회했습니다.
* **개선**: 세션 스토리지에 이미 설정값이 존재하는 경우 불필요한 네트워크 호출을 생략하도록 가드를 추가했습니다.

---

### 6. 서비스 워커 캐시 상향 및 핸드오프 갱신
* **서비스 워커**: `service-worker.js` 캐시 버전을 `kiosk-cache-v370`으로 상향.
* **핸드오프**: `handoff.md`에 P124를 최우선 '구현 완료·배포 대기'로 등록하고 다음 신규 작업 번호를 `P125`로 갱신.

## 배포 안내

이 작업은 **GAS 서버 코드 2개 파일** 수정이 포함되어 있습니다:
1. Google Apps Script 편집기에서 아래 2개 파일 내용을 덮어씌웁니다:
   - `gas/40_Orders.gs`
   - `gas/30_GuestCredits.gs`
2. Apps Script 상단 **[배포] → [배포 관리] → 연필 아이콘(수정) → [새 버전 배포]**를 1회 실행합니다.
3. GitHub Pages는 푸시 후 자동으로 `kiosk-cache-v370`으로 배포됩니다.
