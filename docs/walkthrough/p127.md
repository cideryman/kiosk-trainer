# P127 주방 단계적 일괄 진행, 즉시 완료 분리, 순차 요청 큐 및 로딩 피드백 구현 결과

## 1. 개요
주방 화면(`kitchen.html`)에서 주문 처리 시 발생하던 다음 3가지 문제를 종합적으로 해결했습니다:
1. **연속 탭 시 GAS 타임아웃 방지 (순차 처리 큐)**: 주문 카드를 빠르게 연속으로 누를 때 GAS의 `ScriptLock(10000)` 충돌로 후속 요청이 타임아웃(실패)되던 현상을 프론트엔드 FIFO 큐(`orderMutationQueue`)로 완벽 직렬화(concurrency=1)하여 순차 전송.
2. **버튼 미작동 오인 방지 (즉각적 로딩 상태)**: 버튼 클릭 즉시 회색 비활성화(`is-loading`)와 함께 `⏳ 대기 중...` 또는 `⏳ 처리 중...` 피드백을 제공하여 중복 클릭 방지 및 클릭 상태 명확화.
3. **단계별 일괄 진행 버튼 도입**: 기존 '모두 제공'이 중간 상태(준비시작 P, 준비완료 R - 고객 알림/키오스크 뱃지/TTS)를 건너뛰던 문제를 해결하고, 현재 컬럼 내 가장 앞선 주문을 감지하여 `☕ 모두 준비시작` → `🔔 모두 준비완료`(배달은 `🛵 모두 배달출발`) → `📦 모두 수령완료`로 순차 승급하는 동적 버튼 제공.
4. **즉시 전체 완료 버튼 분리 유지**: 긴급/러시 아워에 모든 중간 단계를 건너뛰고 즉시 전체 완료할 수 있는 `⚡ 즉시 완료` 버튼을 사용자 선호에 맞추어 독립 유지.

## 2. 변경 파일 및 상세 내역

### 1) [js/kitchen.js](file:///c:/Users/주간보호/Desktop/새%20폴더/kiosk-trainer/js/kitchen.js)
- **`orderMutationQueue` 및 `processOrderMutationQueue` 구현**:
  - `enqueueOrderMutation(mutation)`: 카드 개별 상태 변경, 되돌리기, 선택 제공, 일괄 단계 진행, 즉시 전체 완료 등 모든 쓰기 요청을 큐에 적재.
  - 큐 워커가 한 번에 정확히 1건씩 GAS 서버로 전송하며, 모든 처리가 완료된 후 조용한 최신 동기화(`silentRefreshAdminData()`)를 1회 실행.
- **`getColumnStepInfo(columnId, groups)`**:
  - 각 컬럼의 주문 중 아직 시작되지 않은 주문(`N`)이 있으면 `☕ 모두 준비시작 (N건)` 반환.
  - 모두 준비 중(`P`)이면 `🔔 모두 준비완료 (N건)` (배달은 `🛵 모두 배달출발 (N건)`) 반환.
  - 모두 준비 완료(`R`)이면 `📦 모두 수령완료 (N건)` (배달은 `📦 모두 배달완료 (N건)`) 반환.
  - 대기 주문이 없으면 `진행할 주문 없음` 반환 및 버튼 비활성화.
- **`advanceColumnStep(columnId)`**:
  - 확인창 호출 후 해당 단계 대상 주문들을 일괄 큐에 인큐하고 즉각 낙관적 렌더링.
- **`completeSelectedOrders(columnId, skipConfirm)` & `completeAllOrders(columnId)`**:
  - 즉시 전체 완료(`⚡ 즉시 완료`) 실행 시 확인창 중복 없이 큐를 통해 안전하게 순차 완료 처리.
- **`renderData(rawOrders)`**:
  - 주문 카드의 액션 버튼: `isPending` 상태인 경우 즉시 `<button class="btn-complete-action is-loading" disabled>⏳ ${isCurrentlyInFlight ? '처리 중...' : '대기 중...'}</button>`으로 렌더링.
  - 완료 테이블의 되돌리기 버튼: 처리 중일 때 `⏳ 처리중` 및 비활성화.
  - 각 컬럼 상단 바에 `[선택: N건] [선택 제공] [☕ 모두 준비시작 / 🔔 모두 준비완료] [⚡ 즉시 완료]` 4단 구조 배치.
