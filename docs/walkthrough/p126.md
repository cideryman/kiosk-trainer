# 워크스루: 주방 주문 상태 변경 시 자동 새로고침 충돌 방지 및 무소음 갱신 UX 개선 (P126)

주방 화면(`kitchen.html` / `js/kitchen.js`)에서 주문 상태(준비시작, 준비완료, 배달출발, 되돌리기 등)를 조작하는 도중 30초 자동 새로고침 타이머가 발동될 때 발생하던 **DOM 파괴 깜빡임(버튼 사라짐)**, **통신 중 경합(Race Condition)**, **이전 상태로 일시 되돌아가는 현상(Stale Read)**을 근본적으로 방지하여 안정적인 조작 경험을 완성했습니다.

---

## 주요 변경 사항

### 1. 사용자 조작 시 자동 새로고침 타이머 즉시 리셋 (`js/kitchen.js`)
* **현상**: '준비 시작'(`updateStatusAction`), '되돌리기'(`undoCompleteOrder`), '선택 완료'(`completeSelectedOrders`) 등 버튼을 클릭할 때 30초 새로고침 타이머가 리셋되지 않아, 타이머가 1~2초 남은 시점에 조작하면 통신 도중 새로고침이 동시에 발동되는 문제가 있었습니다.
* **개선**: 모든 주문 조작 함수의 진입점에서 `resetRefreshTimer()`를 즉시 호출하여 30초 카운트다운을 처음부터 다시 시작하도록 조치했습니다. 조작 중에는 새로고침이 끼어들지 않습니다.

---

### 2. 자동 새로고침 시 무소음(Silent) 백그라운드 갱신 적용 (`js/kitchen.js`)
* **현상**: 30초 타이머 만료 시 `loadAdminData(true)`가 실행되면서 `pendingContainer.innerHTML = '대기 목록 불러오는 중...'`, `tbody.innerHTML = '데이터를 불러오는 중...'`으로 기존 화면을 통째로 지워버려 손가락 아래의 버튼이 사라지고 클릭이 씹히는 현상이 발생했습니다.
* **개선**:
  * `loadAdminData(isAutoRefresh = false)`에서 `if (!isAutoRefresh)`일 때만 로딩 문구를 표시하고,
  * 자동 새로고침(`isAutoRefresh === true`)일 때는 기존 DOM 카드를 온전히 유지한 채 백그라운드에서 데이터를 페치하여 부드럽게 내용만 갱신(무소음 갱신)하도록 변경했습니다.
  * 백그라운드 새로고침 중 네트워크 지연/오류가 발생하더라도 기존 화면 카드를 삭제하지 않습니다.

---

### 3. 서버 통신 중 새로고침 5초 연기 (`js/kitchen.js`)
* **개선**: `startRefreshTimer()`에서 타이머가 0초에 도달했을 때, 현재 서버로 전송 중인 주문(`pendingUpdates.size > 0`)이 있으면 자동 새로고침을 5초 뒤로 연기(`refreshSeconds = 5`)하여 쓰기-읽기 충돌을 원천 차단했습니다.

---

### 4. 최근 변경 주문 5초 Stale-Read 보호 윈도우 (`js/kitchen.js`)
* **현상**: 구글 시트에 상태 저장이 완료되기 직전이나 완료된 직후 새로고침이 발생하면, 아직 구글 시트에 반영되기 전의 과거 상태(`N` 등)를 받아와 로컬 카드가 이전 상태로 덜컹거리며 되돌아갔다 오는 문제가 있었습니다.
* **개선**:
  * `recentStatusUpdates` 맵을 도입하여 상태 변경 시 5초 동안 보호 윈도우(`RECENT_UPDATE_PROTECT_MS = 5000`)를 설정했습니다.
  * 서버에서 새로고침 데이터를 받아와 렌더링(`renderData`)할 때, 5초 이내에 변경된 주문이 과거 상태로 돌아오면 최신 상태를 유지하도록 보호하고, 서버 데이터가 최신 상태와 일치해지면 보호를 자동 해제합니다.

---

### 5. 서비스 워커 캐시 버전 상향 (`service-worker.js`)
* **개선**: `kiosk-cache-v372` → `kiosk-cache-v373`으로 상향하여 브라우저에 최신 스크립트가 즉시 반영되도록 조치했습니다.

---

### 6. 전용 단위 테스트 추가 (`scripts/test-kitchen-refresh-guard.js`)
* 비파괴적 새로고침(`!isAutoRefresh` 가드) 검증.
* 주문 조작 버튼 호출 시 `resetRefreshTimer()` 호출 여부 검증.
* 통신 중 새로고침 5초 연기 검증.
* 5초 Stale Read 보호 윈도우(옛날 상태 덮어쓰기 방지 및 일치 시 자동 해제, 5초 초과 시 정상 만료) 검증 통과.

## 사용자 수동 검증 안내

1. **GitHub 원격 저장소 푸시 및 Pages 반영**:
   - 수정된 정적 파일들이 푸시되고 GitHub Pages에 반영되면 브라우저를 새로고침(또는 PWA 재실행)하여 `kiosk-cache-v373`을 적용받습니다.
2. **주방 화면 동작 확인**:
   - 주방 화면(`kitchen.html`)에서 30초 카운트다운 타이머를 확인합니다.
   - 타이머가 2~3초 남았을 때 '준비 시작' 또는 '준비 완료' 버튼을 누릅니다:
     - 누르는 순간 타이머가 즉시 30초로 리셋되는지 확인합니다.
   - 타이머가 0초가 될 때:
     - 화면이 "불러오는 중..."으로 깜빡이거나 버튼이 사라지지 않고, 기존 카드들이 그대로 유지되면서 조용히 갱신되는지 확인합니다.
   - 상태 변경 후 카드가 이전 상태로 깜빡이며 되돌아갔다 오는 불안정 현상이 사라졌는지 확인합니다.
